# Issue list

Resolved findings from the 2026-07-18 audit are recorded in [`docs/reviews/review-resolution-v0.1.2.md`](docs/reviews/review-resolution-v0.1.2.md).

## Correctness and trust work

- [x] Replace heuristic compiler-output matching with structured `go test -json` event classification and explicit build diagnostics. `internal/runner.GoTest` now classifies from the `-json` event stream: a package-level `[build failed]` marker (the tool's own FAIL-summary line, emitted identically for compile *and* vet failures) means INVALID; a package that fails before any test starts for a non-build reason (init() panic, `TestMain` calling `os.Exit`, ...) means KILLED with no test attributed; a test still "started" when the stream ends (an unrecovered panic in a goroutine the testing package doesn't supervise, which aborts the binary without a clean per-test fail event) is attributed as responsible. The previous English-substring regex is kept only as a last-resort fallback for the rare case where `go test` rejects the invocation before `test2json` ever writes JSON (e.g. build constraints exclude all Go files). This also fixed a latent attribution bug: the old `--- FAIL: ` line regex was anchored to line-start and silently missed every subtest name, since Go indents nested subtest result lines (`    --- FAIL: TestX/sub`) — a common table-driven-test pattern. "killed by" now correctly includes subtests.
- [x] Add process-signal tests proving temporary-workspace cleanup under abrupt CLI termination. Found and fixed a real bug in the course of this: `cmd/mutation-judge/main.go` used bare `context.Background()` with no signal handling, so Go's default disposition for an unhandled SIGINT/SIGTERM is immediate process termination — deferred sandbox cleanup never ran, confirmed by reproduction (a real `SIGTERM` left the temp sandbox on disk). Fixed with `signal.NotifyContext`, a distinct `exitInterrupted = 130` exit code, and `cmd/mutation-judge/main_test.go`'s `TestSIGTERMCleansUpTemporarySandbox`, which sends a real `SIGTERM` to a real subprocess and checks the sandbox is gone; verified the test fails against the reverted (buggy) code.
- [x] Add a fixed external corpus evaluation with manually reviewed survivors. See `docs/evaluation.md`, "External corpus evaluation" (2026-08-18): three dependency-free real-world libraries (`rs/xid`, `dustin/go-humanize`, `google/uuid`), same bounded operator set, every survivor traced to source. Found two provably equivalent mutants (via a discarded return value and a no-op string replace), several genuine boundary/coverage gaps, and one real bug in `google/uuid`'s own test suite (`TestNullUUIDUnmarshalText` never calls `UnmarshalText`).
- [x] Test cgo, build tags, package initialization failures, custom `TestMain`, and unusual toolchain failures. Added four end-to-end fixtures under `tests/integration/testdata/` (invisible to `./...` expansion): a real cgo package, a build-tag-excluded file proving discovery only mutates what `go list`'s `GoFiles` includes, an `init()` panic (classified KILLED, not INVALID), and a custom `TestMain` calling `os.Exit` before `m.Run()` (classified KILLED with no test misattributed).
- [x] Decide whether publication builds should use full TOML/YAML libraries instead of the documented strict flat subset. Decided: keep the strict flat subset permanently; do not adopt a dependency. See `docs/decisions/0001-config-parser-scope.md` for the full reasoning. Implemented the one concrete improvement the decision pointed to: YAML's native block-list style is now accepted for list-valued keys (`internal/config/config.go`, `readYAMLBlockList`), since it's unambiguous to parse without adopting general nested-YAML parsing.
- [x] Add an explicit warning/evidence field for non-fatal cache write failures. A cache write failure (e.g. a full or unwritable `cache_dir`) was previously silently discarded (`_ = store.Put(...)` in `internal/analysis/analysis.go`), so a person could have no idea caching had stopped working. Now surfaced three ways, deduplicated into one summary message rather than one line per mutant: a new `model.Report.Warnings` evidence field (present in JSON, `omitempty` when empty), a `warnings` section in the text and HTML renderers, and a `warning:` line on stderr. The mutant's own result is unaffected and the run still succeeds — this is explicitly non-fatal. Verified end-to-end against a real blocked cache directory (a regular file where the cache directory should be, which fails reliably regardless of user privilege, unlike a permission-bits approach) via both a unit test (`TestCacheWriteFailureIsReportedAsWarningNotFatal`) and the built CLI binary in all three output formats.
- [x] Add differential fixtures comparing source replacements with manually authored mutants, and expand precedence/parenthesization regression tests for complex boolean expressions. `internal/frontend/differential_test.go` reconstructs the full mutated source for a discovered mutant and byte-compares it against a hand-verified expected string (verified against real `Discover` output before being written down, not hand-calculated), then confirms it still parses as valid Go. Covers `&&`/`||` mixed precedence, left-associative `&&` chains at multiple depths, `!(...)` double-parenthesization (a real, notable finding: `!(a && b)` mutates to `((a && b))`, since the NOT operand is itself a `ParenExpr` whose source already includes its own parens), and boundary comparisons nested inside a boolean tree. Verified the fixtures have teeth by deliberately breaking the parenthesization logic: 4 of 8 failed immediately with a clear diff.
- [x] Add a persistent journal/log entry for abnormal process termination, for post-mortem debugging beyond the exit code and partial report. `cmd/mutation-judge` now appends one NDJSON entry to `.mutation-judge/journal.ndjson` (independent of `--no-cache`) on every SIGINT/SIGTERM: timestamp, which signal specifically (SIGTERM usually means an orchestrator/CI timeout, SIGINT usually means a person), which phase (baseline vs. mutant execution), patterns, operators, and — for the mutant-execution phase — how many mutants had already completed. A journal write failure is itself non-fatal (surfaced on stderr, doesn't change the exit code), matching how the cache-write-warning item above is handled. Signal identity capture required replacing `signal.NotifyContext` with an explicit `signal.Notify` + buffered-channel handoff (`NotifyContext` doesn't expose which signal fired); verified race-free via the channel send happening-before the `cancel()` call. Verified end-to-end with real `SIGTERM` and `SIGINT` against the real binary, plus two permanent regression tests (`TestSIGTERMWritesBaselinePhaseJournalEntry`, `TestSIGTERMWritesMutantsPhaseJournalEntry`) — the latter synchronized off mutation-judge's own `--progress` output rather than a sleep guess, so it reliably lands mid-mutant-execution on any machine speed.
- [x] Fix a real platform-dependent misclassification in `internal/runner.classifyEvents`, found via a genuine `go test ./...` run on macOS (not this development environment, which is Linux): "build constraints exclude all Go files" produces zero JSON events on Linux (correctly handled by the pre-existing fallback path), but on the reporting platform `go test -json` instead emits a package-level `FAIL <pkg> [setup failed]` line — a different bracketed reason word than the `[build failed]` marker the classifier only checked for — so it fell through to KILLED instead of INVALID. Fixed by matching the general `FAIL <pkg> [<reason>]` structure instead of one hardcoded phrase. Added direct unit tests against `classifyEvents` with synthetic events (`TestClassifyEventsRecognizesSetupFailedMarker` reproduces the exact reported scenario verbatim; `TestClassifyEventsRecognizesUnknownReasonWordInFailBracket` proves the fix generalizes rather than adding a second hardcoded phrase) rather than relying only on a real toolchain's platform-specific behavior, which is what let this slip through the original integration-only test the first time. Confirmed both new tests fail against the reverted substring-only check.

## Performance work

- [x] Measure source-tree digest and full-sandbox copy cost on large modules before narrowing either correctness boundary. See `docs/performance.md` and `internal/workspace/workspace_bench_test.go`. `Digest` (read-only) scales cleanly and is inexpensive even at 8000 files (~24MB source, ~100ms). `CopyModule` (write-heavy) is both the more expensive operation and, on the constrained single-vCPU sandbox this was measured on, subject to substantial run-to-run storage I/O variance that swamped any clean scaling signal — repeating the identical input size across separate invocations produced results differing by more than 2x. This does not support narrowing what gets copied (even the worst observed cost is a one-time overhead almost certainly dwarfed by the baseline `go test` run that follows on any project large enough to have thousands of files), but it does support prioritizing the next item below, since it targets exactly the write path shown here to be both the more expensive and the more variable one.
- [ ] Explore copy-on-write/reflink sandbox creation where the host filesystem supports it.
- [ ] Add coverage-guided package/test sharding.
- [ ] Add parallel isolated workers with deterministic output ordering.
