# Issue list

Resolved findings from the 2026-07-18 audit are recorded in [`docs/reviews/review-resolution-v0.1.2.md`](docs/reviews/review-resolution-v0.1.2.md).

## Correctness and trust work

All items in this section are done. Summaries stay here as the audit trail; see git history for the implementations.

- [x] Replace heuristic compiler-output matching with structured `go test -json` event classification and explicit build diagnostics. `internal/runner.GoTest` now classifies from the `-json` event stream: a package-level `FAIL <pkg> [<reason>]` marker (compile, vet, or setup) means INVALID when that package never started a test of its own; a package that fails before any test starts for a non-build reason (init() panic, `TestMain` calling `os.Exit`, ...) means KILLED with no test attributed; a test still "started" when the stream ends is attributed as responsible. The previous English-substring regex is kept only as a last-resort fallback when `go test` rejects the invocation before `test2json` writes JSON. Nested subtest `--- FAIL:` lines are matched (leading whitespace). Classification is per package, so a sibling package's passing tests cannot turn another package's compile failure into a counted KILL on `./...`.
- [x] Add process-signal tests proving temporary-workspace cleanup under abrupt CLI termination. `cmd/mutation-judge/main.go` handles SIGINT/SIGTERM, exit code `130`, sandbox cleanup, and an NDJSON journal entry at `.mutation-judge/journal.ndjson`.
- [x] Add a fixed external corpus evaluation with manually reviewed survivors. See `docs/evaluation.md`, "External corpus evaluation" (2026-08-18).
- [x] Test cgo, build tags, package initialization failures, custom `TestMain`, and unusual toolchain failures (`tests/integration/testdata/`).
- [x] Keep the strict flat TOML/YAML subset permanently; do not adopt a parser library. YAML native block lists for list-valued keys are accepted. See `docs/decisions/0001-config-parser-scope.md`.
- [x] Surface non-fatal cache write failures as `model.Report.Warnings`, in text/HTML, and on stderr.
- [x] Differential fixtures for source replacements and boolean parenthesization (`internal/frontend/differential_test.go`).
- [x] Persistent journal on SIGINT/SIGTERM (baseline vs mutant-execution phase).
- [x] Platform `FAIL <pkg> [setup failed]` (and any other bracketed reason) classified INVALID, not KILLED.
- [x] Multi-package `./...` compile failure classified INVALID even when a sibling package's tests run.
- [x] Cache key and report toolchain fields come from `go env GOVERSION GOOS GOARCH CGO_ENABLED GOFLAGS` (`runner.DetectToolchain`), not `runtime.Version()`.
- [x] `Digest` hashes exactly the file set `CopyModule` places in the sandbox (`sandboxEntries`). Outbound-symlink policy and skip rules for `node_modules` / non-Go root `bin/` / non-modules.txt `vendor/` are implemented (optional expansion below updated).
- [x] Reject multi-module `go.work` workspaces in `ModuleRoot` (single-module workspace or `GOWORK=off` still allowed). Prevents analyzing under workspace replace/selection that a single-module sandbox cannot represent.
- [x] Host `GOWORK` leaking into every `go test`/`go list` invocation. Two gaps, both real, both closed: (1) `ModuleRoot`'s workspace check only counted `use` entries, so a *single*-module `go.work` carrying a `replace` directive passed it untouched -- a workspace-level replace rewrites dependency resolution exactly like a module-level one, but lives outside the module root `workspace.Digest` hashes, so identical module bytes with a different active replace digested identically and shared a cache entry despite testing different resolved dependencies. `rejectUnsafeWorkspace` (renamed from `rejectMultiModuleWorkspace`) now also rejects any replace-bearing `go.work`, with the same "re-run with `GOWORK=off`" remediation as the multi-module case, via new `goWorkReplaceCount`. (2) `runner.GoTest.Run` executed with a nil `Env`, inheriting whatever `GOWORK` the mutation-judge process itself ran under -- but its `cmd.Dir` is always a temporary sandbox copy of the module root alone (`workspace.CopyModule`), never one of a `go.work`'s `use`-listed directories, so an inherited workspace either resolved dependencies outside the sandbox or made `go test` refuse to run there ("not in any workspace module"). `GoTest.Run` now sets `cmd.Env = append(os.Environ(), "GOWORK=off")` unconditionally, independent of what `ModuleRoot`'s check already ruled out upstream. Added `TestGoWorkReplaceCount`, `TestRejectWorkspaceWithReplace`, `TestSingleModuleWorkspaceWithoutReplaceIsAllowed` (`internal/workspace`), and `TestGoTestRunIgnoresHostGOWORK` (`internal/runner`) -- confirmed each fails against the pre-fix code with the exact symptom described (a real "not in any workspace module" error from `go test` for the runner case).
- [x] `parseGoWorkUsePaths`/the workspace-check's `use`/`replace` parsing matched fixed literal substrings (`"use ("`, `" //"`) instead of tokenizing `(` as its own token, so two syntactically ordinary go.work layouts -- `use(` with no space before the paren, and `use ( // comment` with a trailing line comment on the opening-paren line -- both produced zero recognized `use` entries and silently bypassed the multi-module rejection entirely (a real two-module `go.work` written either way was treated as single-module). Replaced with `goWorkDirectiveArgs`, a small shared tokenizer (`cutVerb` + `stripLineComment`) used by both the `use`-path and `replace`-count parsing, that recognizes `(` as a block opener regardless of surrounding whitespace or a same-line trailing comment. Added `TestParseGoWorkUsePathsHandlesParenWithoutSpace`, `TestParseGoWorkUsePathsHandlesCommentOnOpenParenLine`, and the end-to-end `TestRejectMultiModuleWorkspaceSurvivesParenLayoutVariants` -- confirmed each fails against the pre-fix parser with a real `ModuleRoot` bypass, not just a wrong parse result.
- [x] `skipSandboxDir` matched `d.Name() == "vendor"` at any depth, not just the module root. Go's vendor consistency mechanism (`-mod=vendor`, `vendor/modules.txt`) only ever applies to the main module's own top-level `vendor/`; a directory that merely happens to be named `vendor` deeper in the tree (`cmd/vendor`, `pkg/vendor`, ...) is an ordinary directory as far as `go build`/`go test` are concerned, and can be a real, importable Go package. The blanket name match dropped it from both the sandbox copy and the digest, so anything importing it built fine on the host but failed (misclassified `INVALID`, missing package) in the sandbox. Fixed by scoping the `modules.txt`-based check to `filepath.Rel(rootAbs, path) == "vendor"`; every other `vendor`-named directory is now treated exactly like any other directory, never skipped by name alone. (`node_modules` is a different case and was left as-is: it's skipped at every depth deliberately, and unlike `vendor` there's no realistic scenario where a Go import path needs a path segment literally named `node_modules`, so the blanket match there isn't a live bug.) Added `TestSandboxKeepsNonRootVendorNamedPackage`, which actually runs `go build ./...` against the copied sandbox tree (not just checking the file's presence) -- confirmed it fails against the pre-fix code with a real missing-package build error, matching the reported symptom exactly. Updated `TestSandboxSkipsNodeModulesJunkVendorAndRootBin`'s `third_party/vendor` assertion to match the corrected (kept, not skipped) contract.
- [x] `notNilOperand` (the `errorreturn` operator's `if X != nil` detector) unwrapped parens on `cond` as a whole, but never on the two operands of the resulting `!=` comparison. `if (err != nil)` matched (the existing `TestDiscoverErrorReturnUnwrapsParens` covers exactly this), but `if (err) != nil` and `if err != (nil)` did not: `isNilIdent` received a `*ast.ParenExpr` instead of a bare `*ast.Ident` on whichever side happened to be parenthesized, so the type assertion inside it failed either way -- for `if (err) != nil` this made the nil-check still succeed (via the *other*, un-parenthesized side) but returned the parenthesized `(err)` as the "checked" value, which then failed the caller's own `checked.(*ast.Ident)` assertion in `frontend.go`'s `*ast.IfStmt` case; for `if err != (nil)` neither operand read as a bare nil identifier at all, so the whole comparison went unrecognized and `notNilOperand` returned `false`. Fixed by unwrapping both `be.X` and `be.Y` once in `notNilOperand` and using the unwrapped values for both the nil check and the returned "checked" operand. Added `TestDiscoverErrorReturnUnwrapsParensOnEitherOperand` (both shapes, as subtests) -- confirmed each fails against the pre-fix code (`if (err) != nil` and `if err != (nil)` each produced zero mutants).
- [x] `gitdiff.ChangedLines`' `git diff` invocation left `core.quotepath` at its default (`true`), so a genuinely modified file whose name contains a non-ASCII byte (or a literal quote/backslash) comes back with a C-quoted, octal-escaped `+++ "b/caf\303\251.go"` header instead of plain `+++ b/café.go`. `Parse`'s `+++ ` / `b/`-prefix matching does not recognize the leading `"`, treats the file as unset, and silently drops every hunk for it -- so under `--changed <base>`, a real edit to any such file was treated as having no changed lines at all (zero mutants surfaced for it) rather than erroring or being included. This code path (the real `git diff` subprocess, as opposed to `Parse` on synthetic bytes) had no test coverage at all before this. Fixed by passing `-c core.quotepath=false`, which makes git always emit raw, unescaped UTF-8 path headers (`Parse` already handles those correctly). Added `TestChangedLinesHandlesNonASCIIFilename` (a real git repo with a `café.go` file) -- confirmed to fail against the pre-fix invocation with an empty result for that file.
- [x] Timeout classification: outer `context.DeadlineExceeded` is definitive; the text fallback matches only `^panic: test timed out after ` on a failed process.

## Optional feature expansion

- [ ] Distributed CI manifests: split one run's mutants across separate jobs/machines and merge JSON reports. Distinct from `--workers`, which parallelizes within one process. See `docs/performance.md`.
- [x] SARIF and GitHub annotation rendering. `--format sarif` (SARIF 2.1.0) and `--format github` (workflow-command annotations on stdout). Only `SURVIVED`, `TIMEOUT`, and `UNKNOWN` produce findings. See `docs/tutorial.md` section 15.
- [x] Targeted operators for error returns, switch cases, loops, and channels (`errorreturn`, `switch`, `loop`, `channel`; all opt-in). See `docs/semantics.md`. Further operators are a separate item below.
- [x] Cross-run comparison and score trend. `compare` diffs two `--format json` reports into six buckets (`new_survivors`, `fixed_survivors`, `still_open`, `reclassified`, `removed_mutants`, `unchanged_count`) plus `likely_shifted`. `record`/`trend` keep `.mutation-judge/history.ndjson`. Text, JSON, and HTML (`--format html`, `internal/compare.RenderHTML`) are all implemented -- the same six buckets and shift correlations as a self-contained, browsable page, styled to match the single-report HTML output's verdict colour-coding.
- [x] Conservative equivalent-mutant suppression for locally provable guarded comparisons. Implemented for the exact shape this item named: a boundary comparison dominated by an `if X != Y { return X < Y }`-shaped guard on the same two operands is classified `EQUIVALENT` and never executed (`internal/frontend.detectGuardedComparison`). Confirmed against the real `sort.Slice` comparator in `internal/frontend.Discover` (`docs/evaluation.md`, "Guarded sort comparisons"). Deliberately narrow -- see `docs/limitations.md` limitation 7 and `docs/semantics.md`.
- [ ] Cross-run HTML comparison (text and JSON `compare` already ship).
- [x] Added a fifth opt-in operator, `assignment`: swaps `+=`/`-=` and `*=`/`/=` (mirroring `arithmetic`'s four operators one level up, at the compound-assignment statement instead of the binary expression), and swaps `++`/`--`. Carries the same timeout-safety rule as `loop`/`channel`: never mutates a statement that is exactly a `for` statement's own `Post` clause, since flipping a counting loop's increment direction there produces a guaranteed TIMEOUT rather than a KILLED/SURVIVED for essentially any ordinary counting loop -- confirmed as a real, not hypothetical, risk: removing the exclusion during development produced an actual mutant rewriting `for i := 0; i < len(xs); i++` to `...i--`. A variable manually incremented in a loop's *body* rather than its `Post` clause is an honest, disclosed limitation (no data-flow analysis), not something this exclusion catches. Bumped `SemanticsVersion` to `v4`. Added `examples/assignment` (1 killed, 2 survived) and 5 new frontend tests, including one proving the for-loop-post exclusion against a reverted version of the code.
- [x] Added a sixth opt-in operator, `relational`: Relational Operator Replacement restricted to equality -- swaps `==`/`!=`, the one relational pair `boundary`'s `</<=/>/>=` swap doesn't already cover. Needs its own loop-safety exclusion, for a different reason than `assignment`'s: a boundary swap only ever shifts a monotonic threshold by one step, so it cannot change whether a comparison eventually flips as a loop variable progresses the same direction it always did, but an equality/inequality swap inverts a comparison's polarity outright -- `for x != target {...}` mutated to `for x == target` can run zero times or forever depending on `x`'s actual trajectory. Refuses to mutate any `BinaryExpr` appearing anywhere within a `for` statement's own condition, including nested inside a compound `&&`/`||` -- not just a bare top-level comparison. Bumped `SemanticsVersion` to `v5`. Added `examples/relational` (1 killed, 1 survived) and 2 new frontend tests, including one proving the loop-condition exclusion (nested in `&&`) against a reverted version of the code.
- [x] Added a seventh opt-in operator, `literal`: mutates an integer literal into two mutants, its value plus one and minus one, parsed via `go/constant` (not a naive `strconv` call) so hex/octal/binary/underscore-separated literals are all read correctly regardless of the replacement text always being plain decimal. Skips a literal sitting exactly on the `int64` boundary, since `n+1`/`n-1` would silently wrap around in Go's own arithmetic at that exact edge -- confirmed this was a real bug during development (not hypothetical) by removing the guard and watching `9223372036854775807` "increment" to `-9223372036854775808`, then fixing it before it shipped. Needs two loop-safety exclusions, reusing the same `for`-statement tracking `assignment` and `relational` already build: a literal inside a loop's own post clause is exactly as dangerous as the operator it's an operand of (`i -= 1` mutated to `i -= 0` removes the loop's only progress toward termination); a literal inside a loop's own condition is excluded too, out of caution for an exotic non-monotonic loop whose termination depends on hitting an exact value, even though an ordinary threshold shift there is no more dangerous than `boundary`'s own swap. A loop's *init* value carries neither risk and is mutated normally. Bumped `SemanticsVersion` to `v6`. Added `examples/literal` (4 killed, 2 survived) and 5 new frontend tests, including one proving each loop-safety exclusion and one proving the `int64`-boundary guard, all confirmed to fail against a reverted version of the code.
- [x] Extended `literal` to also mutate non-empty string literals (`*ast.BasicLit` with `Kind == STRING`), replacing one with `""`, via `strconv.Unquote` to correctly decode both interpreted and raw (backtick) string syntax before checking for emptiness. The existing loop-condition/post exclusions apply automatically, since the tracking map is keyed by `*ast.BasicLit` regardless of kind (`for s != "done" { ... }` is exactly as susceptible to the same exotic non-monotonic-termination risk an integer-equality loop is). Found and fixed a real, non-hypothetical gap during development: an `*ast.ImportSpec`'s own path is itself a string `*ast.BasicLit`, so without an explicit exclusion this would have emptied `import "fmt"` to `import ""` -- a guaranteed compile failure on essentially every Go file, since nearly every file imports something. Not a timeout-safety issue like the loop exclusions; just a mutant that could only ever be a 100%-certain, zero-information `INVALID` verdict, confirmed by reproducing it end to end before adding the fix. Bumped `SemanticsVersion` to `v7`. Extended `examples/literal` with a `Greeting`/`DefaultName` fixture (now 5 killed, 3 survived overall) and added 4 more frontend tests, including one proving the import-path exclusion against a reverted version of the code.
- [ ] Further operators beyond the seven opt-in families now implemented. Same timeout-safety rule: never generate a mutant whose expected verdict is an uninformative `TIMEOUT`.
- [x] Coverage-attributed per-test selection, `--coverage-test-selection` (opt-in, default off, independent of and stackable on `--narrow-test-scope`). Implements the "much heavier machinery" `--narrow-test-scope`'s own doc had already named and deferred: aggregate `-coverprofile` data says a line executed somewhere in a run, never by which test, so per-test attribution means running every top-level test in every test-bearing package individually (`runner.ListTests` for enumeration via `go test -list`, then one `go test -run '^Name$' -coverprofile=...` per test), recorded in a new `coverage.PerTest` type that reuses `Map.Covered` unchanged per test rather than reimplementing suffix matching. A mutant's `-run` narrows to the union of covering tests across every line in its span (not just its first line) via a new `mutantTestRun`, mirroring `mutantTestScope`'s existing fallback contract exactly: the actual computed `-run` string is now its own explicit cache-key component (same class of bug the original scope-string fix addressed, now extended), a person's own already-set `--test-run` disables the feature entirely rather than attempting to compose two regular expressions, and a known-but-confidently-empty covering set never narrows to a pattern that would run zero tests. Any failure building the per-test map at all -- most notably a test that fails when run in isolation despite passing as part of the validated full baseline, a real and not hypothetical signal of an order-dependent or shared-mutable-state test -- disables coverage-test selection for the *entire* run with a warning, never a partial per-package result. Added `internal/coverage/pertest.go` (5 unit tests), `runner.ListTests` (3 tests, including a real build-failure case), `TestMutantTestRunFallsBackWhenUncertain` (5 subtests covering every fallback branch), `TestBuildPerTestCoverageAttributesCorrectly` and `TestBuildPerTestCoverageFailsWhenATestFailsInIsolation` (both real-backend, the latter constructing a genuine inter-test dependency and confirming it's caught), and an end-to-end integration fixture (`tests/integration/testdata/coverage_selection`, mirroring `testdata/scoping`'s existing proof technique exactly: an unrelated 3-second test gives an unambiguous, non-flaky timing signal) proving both that the real narrowing happens (mutants-phase timing) and that it never produces a false SURVIVED. The per-test profiling phase's own cost is not currently broken out as its own `timing` field (documented as a known, accepted gap in `docs/performance.md`, the same kind of already-existing gap as sandbox-copy cost not being separately itemized either).
- [x] Outbound-symlink sandbox policy. Symlinks whose target resolves outside the module root are omitted from both `CopyModule` and `Digest` (no host-escape links in the sandbox, no cache-key influence). Internal and in-tree dangling links are still recreated and fingerprinted by target string. Absolute in-tree targets are rewritten on copy to a path relative to the sandbox link (`sandboxSymlinkTarget`) so a test that opens the link sees the sandbox copy `Apply` mutates, not the host file; `Digest` fingerprints those as `abs:` plus the module-relative path so a different checkout prefix does not churn the cache. `TestSandboxRewritesAbsoluteInTreeSymlinks` applies a mutant and reads it through the rewritten link.
- [x] Skip directories that cannot change a Go test verdict: any `node_modules/`; module-root `bin/` with no `*.go` files; `vendor/` without `modules.txt`. Real `vendor/` trees (`modules.txt` present) and non-root `bin` packages are always kept.
- [ ] macOS `clonefile(2)` sandbox clone. Linux `FICLONE` exists; `TestTryReflinkClonesOrCleanlyDeclines` skips where the filesystem cannot clone.
